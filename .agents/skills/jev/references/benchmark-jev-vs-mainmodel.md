# 实测报告：用 Jev 分流 vs 主模型直接判断（tokens 消耗 & 内容质量）

> 数据来源：2026-09-20 真实工作会话，约 18 次 Jev 调用（通道：OpenCode Zen `jev-1.13-free`）。
> 对照任务：电商店铺评论分流（判断"是否需要回复/归哪类/优先级"）。
> 复现命令见文末。**Jev 通道全部为实测值；主模型通道标注了估算依据。**

## 一、Token 消耗对比

### 单条评论三问并行（分类 + 是否提问 + 优先级）

| | Jev 通道 | 主模型通道 |
|---|---|---|
| 输入 | **517 tok / 次（实测，3 连发逐字节相同）** | ~300 tok（评论+指令，估算） |
| 输出 | **80 tok / 次（实测）** | ~200 tok 判断文本（估算） |
| 费用 | **$0（18/18 次响应 cost=0）** | 按 token 计费 |
| 进对话上下文 | **仅 1 行结论（~20 tok）** | 判断文本永久驻留上下文 |

### 关键差异：上下文驻留乘数

主模型做的判断会**留在上下文里被后续每一轮重复计费**。一次 300 tok 的判断，在剩余 50 轮的会话里最多被重复计费 ~1.5 万 tok（有缓存折扣，但量级不变）。Jev 的结论只有一行，驻留成本忽略不计。

### 批量场景（N=50 条评论，每条 ~500 字）

| | Jev 通道 | 主模型通道 |
|---|---|---|
| 原始文本去哪 | 留在脚本里，**不进上下文** | 全部读进上下文 ≈ 2~4 万 tok |
| 上下文净增 | **~50 行结论 ≈ 1-2k tok** | 原文 + 判断 ≈ 3 万 tok 起，且逐轮放大 |
| Jev 侧消耗 | ~2.6 万 input tok（**$0**） | — |
| 额外 prompt 次数 | 0（脚本在回合内跑完） | 0 |

**结论：批量初筛场景 Jev 通道上下文净增约为直读方案的 1/20 ~ 1/30，且判断本身零费用。**

### 本次会话累计（18 次调用）

输入 278~694 tok/次，输出 19~92 tok/次，合计 ~8.5k input / ~1k output，**总成本 $0**。同一会话里等量的主模型判断（逐条读 + 推理 + 驻留）估算消耗其 10~30 倍的等效 token。

## 二、内容质量对比

### 1. 格式可靠性：18/18

18 次调用全部返回合法类型化 schema（noul 概率 / choice+分布+置信度 / score+分级概率），**零格式错误、零解析失败**。主模型自由文本判断需要写解析逻辑，且有格式漂移风险（这是把 LLM 判断接进代码的经典痛点）。

### 2. 一致性：同请求 3 连发实测

| 指标 | 3 次结果 | 波动 |
|---|---|---|
| is_question (noul) | 0.98 / 0.98 / 0.98 | **σ = 0** |
| category (choice) | pre_sales ×3，conf 0.99，概率分布一致 | 无 |
| priority (score) | 1.18 / 1.19 / 1.18 | ±0.01 |
| usage | 517 in / 80 out ×3 | 逐字节相同 |

主模型对同一输入的判断会随措辞/采样波动，且无法给出这种校准概率。

### 3. 决策正确性 A/B：与主模型判断一致

同一批 3 条评论，Jev 结论 vs 主模型（GLM 主模型复核）：

| 评论 | Jev 判定 | 主模型复核 |
|---|---|---|
| "1L反应釜配PT100探头吗?能配数显表吗?" | REPLY · pre_sales · prio 1.2 | ✅ 一致（售前提问，需回复） |
| "旋蒸真空度上不去,哪里漏气?" | REPLY · tech · prio 1.4 | ✅ 一致（技术问题，优先回） |
| "宝贝收到了,包装很仔细,好评!" | defer | ✅ 一致（无需回复） |

**决策质量持平**——原子化的小判断上，免费决策模型和旗舰主模型结论一致。

### 4. 诚实的噪点记录（质量边界）

- 纯好评那条被 Jev 的 `category` 标成了 `logistics`（应为 other）——**但最终决策 defer 依然正确**，因为决策由 `is_question` 门控。**教训：消费主判断（门控），次级标签只做参考**，这与 TypeSafe 官方"原子问题 + 阈值门"建议一致。
- 复杂语义（讽刺、阴阳怪气、跨段落诉求）超出"专家几秒直觉判断"范围，主模型更强。**缓解：Jev 置信度 < 阈值时升级给主模型**（官方 extraction cascade 模式）。

### 5. 稳定性

2 次 Zen 网关瞬时 500（同 payload 重试即成功），`jev.py` 内置退避重试后 **18/18 最终成功**。WAF 403（裸 urllib UA）与 GBK 管道中文两个 Windows 坑已内置修复。

## 三、结论

| 维度 | 赢家 | 依据 |
|---|---|---|
| Token 成本 | **Jev** | $0；批量场景上下文净增 1/20~1/30 |
| 格式可靠性 | **Jev** | 18/18 类型化返回 |
| 一致性 | **Jev** | 3 连发 σ=0 |
| 校准置信 | **Jev** | 概率+confidence，可做阈值门控 |
| 深度理解/复杂语义 | 主模型 | 讽刺、长文综合仍需主模型 |
| 生成类任务 | 主模型 | Jev 不是生成模型 |

**分工原则：判断下沉给 Jev（免费、类型化、不占上下文），生成与综合留给主模型；低置信度时 Jev 升级给主模型。**

## 四、复现

```bash
# 单条三问
echo '{"state":{"comment":"请问1L的反应釜配的是PT100吗?"},"questions":{"is_question":{"type":"noul","instructions":"买家是在提问吗?","criteria":{"true":"询问参数/使用/物流","false":"闲聊/纯评价"}},"category":{"type":"choice","instructions":"归到哪类?","criteria":{"pre_sales":"售前","tech":"技术","logistics":"物流","other":"其他"}},"priority":{"type":"score","instructions":"回复优先级?","criteria":["可次日回","当天回","尽快回"]}}}' | python jev.py
# 批量
python examples/comment_triage.py comments.json
```
